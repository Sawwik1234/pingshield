# PingShield

<div align="center">

**Защита игрока от плохого соединения для Paper, Purpur и Folia.**

[![Сборка](https://github.com/Sawwik1234/pingshield/actions/workflows/build.yml/badge.svg)](https://github.com/Sawwik1234/pingshield/actions/workflows/build.yml)
[![Java](https://img.shields.io/badge/Java-25-orange?logo=openjdk)](https://adoptium.net/)
[![Лицензия: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

</div>

PingShield нужен для ситуации, когда соединение игрока портится настолько, что клиент и сервер начинают по-разному видеть происходящее. Плагин может ненадолго удержать игрока на месте и защитить от урона, пока связь не стабилизируется.

Есть важное правило: **защита от лага не должна становиться преимуществом в PvP**. Замороженный игрок не наносит урон в ответ и не переключается в креатив или наблюдателя.

**Текущая версия:** 1.6.10 · **Java:** 25 · **Paper API:** 26.1.2 · **Folia:** поддерживается

> PingShield использует `Player#getPing()` как показатель качества соединения, а не как точное измерение сетевого RTT. За прокси backend может видеть задержку до прокси, а не задержку между игроком и прокси. Подробнее — в разделе [«Сервер за прокси»](#сервер-за-прокси).

## Возможности

<details>
<summary><b>Защита без PvP-преимущества</b></summary>
<br>

Во время заморозки PingShield удерживает игрока на месте, отключает входящий и исходящий урон и блокирует действия, которые могли бы повлиять на мир. Игровой режим игрока не меняется.

По умолчанию используется режим `PASSIVE`. Также доступны `TELEPORT` и `FLY`. Для случаев, когда постоянная заморозка только мешает, есть `IMMUNITY_ONLY`: игрок может двигаться и взаимодействовать с миром, но урон не проходит ни в одну сторону.

</details>

<details>
<summary><b>Безопасное снятие защиты</b></summary>
<br>

Заморозка может начаться в неудобном месте. PingShield поддерживает запас воздуха под водой, сбрасывает накопленное замерзание в порошковом снегу и проверяет опасные условия — например, огонь или удушье — перед тем, как снять защиту. Есть и защита от кика «Flying is not enabled», если игрок замер на высоте.

Если сервер аварийно завершился во время заморозки, в данных игрока остаётся маркер восстановления. При следующем входе PingShield пытается вернуть изменённые свойства. Если один шаг восстановления не сработал, остальные всё равно выполняются, маркер сохраняется и назначается повторная попытка; после смерти состояние также проверяется при респауне.

Льгота к урону падения и `Slow Falling` нужны только когда игрок отпускается в воздухе. Если защиту сняли на земле, следующий прыжок или падение не получают бесплатной защиты.

</details>

<details>
<summary><b>Скачок сети и лаг сервера</b></summary>
<br>

Проблему одного игрока важно отличать от общей просадки. PingShield следит за распределением пинга онлайн-игроков и ищет массовый скачок. По умолчанию он временно поднимает порог входа, а не замораживает весь сервер. Отдельный `server-lag-guard` может приостановить новые автоматические защиты, если TPS слишком низкий или высокий пинг наблюдается у большой части онлайна.

Есть также проверка пингового шторма по подсетям и политика хронического пинга. По умолчанию хронический пинг приводит к уведомлению, а не к автоматическому кикку.

Сводка по сети доступна в `/pingshield net`.

</details>

<details>
<summary><b>Как работает детектор в версии 1.6.8</b></summary>
<br>

По умолчанию пинг проверяется раз в секунду. PingShield сглаживает замеры с помощью EWMA, учитывает jitter и ждёт несколько последовательных измерений выше порога. Для снятия защиты используется отдельный, более низкий порог — так она не мигает при каждом колебании соединения.

Для автоматического решения важны и последовательность сырых замеров, и сглаженный пинг; jitter может дополнительно поднять порог входа. Общий монитор сети считает медиану и p90 пинга игроков.

Это набор конкретных правил на основе оценки пинга из API, а не адаптивный анализатор сетевых аномалий. В версии 1.6.8 плагин не анализирует отдельные пакеты и не вычисляет confidence-score.

`/pingshield profile <игрок>` показывает сырой и сглаженный пинг, jitter, пороги и число недавних активаций. `/pingshield net` показывает общую картину по сети.

</details>

## Установка

1. Скачайте `PingShield-1.6.10.jar` из комплекта этой версии.
2. Поместите JAR в папку `plugins`.
3. Перезапустите сервер.
4. Проверьте сообщение PingShield в консоли и просмотрите `plugins/PingShield/config.yml`.

Релиз проверялся smoke-тестом на Folia 26.1.2. Проект собран под Paper API 26.1.2 и рассчитан на Paper, Purpur и Folia 26.1.x с Java 25.

## Команды

Основная команда — `/pingshield`; алиасы: `/pshield`, `/pingprotect` и `/pp`.

| Команда | Назначение |
|---|---|
| `/pingshield help` | Показать подсказку |
| `/pingshield status` | Список игроков под защитой |
| `/pingshield check <игрок>` | Пинг, пороги и состояние игрока |
| `/pingshield profile <игрок>` | Профиль пинга и недавние активации |
| `/pingshield net` | Статистика общей сети и состояние детектора скачка |
| `/pingshield protect <игрок>` | Включить защиту вручную |
| `/pingshield unprotect <игрок>` | Снять защиту вручную |
| `/pingshield info` | Версия плагина и состояние интеграций |
| `/pingshield perf` | Время цикла и серверные метрики |
| `/pingshield reload` | Перезагрузить конфигурацию |
| `/pingshield perms <игрок>` | Эффективные права и источник порога |
| `/pingshield via` | Информация о клиентских протоколах Via |
| `/pingshield cp <игрок>` / `/pingshield search` | Поиск связанных записей CoreProtect |

По умолчанию команды доступны операторам. Для персонала можно выдать `pingshield.admin` или отдельные права, например `pingshield.command.status` и `pingshield.command.net`. Право `pingshield.bypass` исключает игрока из автоматической защиты.

## Настройки

Начать можно с порогов и режима заморозки. Значения ниже используются по умолчанию:

```yaml
ping:
  enter-threshold-ms: 3000
  exit-threshold-ms: 2000
  check-interval-ticks: 20

freeze:
  mode: PASSIVE
  invulnerable-flag: true

abuse:
  chronic-ping:
    action: NOTIFY
```

Полный `config.yml` с пояснениями создаётся при первом запуске. В нём есть настройки миров, правил взаимодействия, безопасного снятия защиты, лимитов и сообщений. Меняйте по одной настройке и сначала проверяйте результат на тестовом сервере. После правок выполните `/pingshield reload`.

## Необязательные интеграции

PingShield работает и без дополнительных плагинов. Если они установлены, доступны такие интеграции:

- **LuckPerms** — персональные пороги и режимы заморозки через права и meta. См. [справочник LuckPerms](docs/luckperms.md).
- **ViaVersion / ViaBackwards** — определение протокола клиента и настроенные поправки к порогам.
- **CoreProtect** — маркеры начала и конца защиты, а также проверка изменений вокруг игрока после её снятия.

### Сервер за прокси

За Velocity или BungeeCord `Player#getPing()` может не отражать задержку между игроком и прокси. Режим `proxy.mode: AUTO` пытается распознать локальное подключение и отключает автоматическую защиту, если backend не получает подходящий для этого решения пинг. Включайте `proxy.mode: ENABLE`, только если знаете, что именно показывает пинг в вашей конфигурации. Ручные команды защиты при этом остаются доступны.

## Логи и проверка

`plugins/PingShield/audit.log` содержит события защиты, восстановления и сетевые предупреждения. Если что-то работает не так, проверьте его вместе с консолью сервера. Для быстрой диагностики пригодятся:

- `/pingshield info` — версия и интеграции;
- `/pingshield check <игрок>` — состояние конкретного игрока;
- `/pingshield net` — общая ситуация с сетью;
- `/pingshield perf` — измеренное время цикла.

Полная инструкция по проверке плагина есть в [документе «Как проверить»](docs/kak-proverit.md), а список обработанных причин урона — в [аудите урона](docs/damage-audit.md).

## Сборка и тесты

Для сборки нужен JDK 25. В проекте используется Gradle Wrapper:

```bash
./gradlew build       # сборка, тесты и JAR
./gradlew simulate    # симуляция нескольких профилей соединения
./gradlew load        # синтетическая проверка горячего цикла
```

В Windows используйте `gradlew.bat`. Нагрузочный стенд — синтетический замер, а не обещание одинаковой производительности на любом сервере. Плагин работает через публичный Paper API: NMS и рефлексия не используются.
